# 入力キーワード追加時の配線チェックリスト

.ofd の BPM キーワードを追加/変更するときは、以下を **全部** 揃えて 1 コミットに
すること。片方だけ直すと CPU/CUDA の機能差やサイレント無視が生まれる
(過去に何度も発生)。

## チェックリスト

1. `include/obpm.h` — `BPM` 構造体へフィールド追加 (コメントに単位と既定値)
2. `sol/input_data.c` — 既定値の初期化 + パース (`errfmt2` で不正値を弾く)
3. `sol/solve_bpm.cpp` — CPU 実装 (近軸パスと wabpm パスの **両方** を検討)
4. `cuda/solve_bpm.cu` — CUDA 実装。**未対応にする場合は必ず実行時 warning**
   (サイレント無視は禁止。既存の「無効キーワード警告」ブロックに追加)
5. `data/` — 動作サンプル .ofd (期待される物理挙動をコメントで明記)
6. `ReadMe.md` — キーワード表 (`### BPM 用キーワード`) へ行追加
7. CI — 必要ならスモーク追加 (少なくとも全サンプルスモークで回ること)

## BPM で無効な FDTD キーワード

planewave / point / load / rfeed / abc=1 / pbc は BPM では無効。
`sol/solve_bpm.cpp` と `cuda/solve_bpm.cu` の警告ブロックが検知して
warning を出す。**新たに「BPM では使わない」キーワードを増やす場合も
このブロックへ追加**する。

## CPU/CUDA パリティの原則

- 機能は原則 CPU → CUDA の順で両対応。CUDA 側が後回しになる場合は
  (a) CUDA 側に warning、(b) ReadMe に「CPU のみ」と明記、の両方を行う。
- モード計算のような前処理は CPU で計算して初期電界としてデバイスへ渡す
  方式で良い (カーネル移植は必須ではない)。
